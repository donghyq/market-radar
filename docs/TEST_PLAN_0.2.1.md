# Market Radar 0.2.1 测试报告

2026-11-28 本地实测。基线为开发前的 `a0088d5`，候选规则版本为 `0.2.1.7`。规则开发使用免登录 V2EX 主帖与回帖、App Store 评价及本地归档，标注保留来源。App Store 按应用划分样本，V2EX 按主题划分。用于修改规则的样本在下表标记为回归。

## 识别效果

App Store 的旧版命中指原有评论意图规则至少命中一项。V2EX 原帖对比旧版清洗后可用与新版需求证据判定，使用同一批输入。V2EX 回帖为新增采集渠道，单独报告当批回帖的识别结果。查全率分母为已标注的有效证据，查准率分母为规则命中数。

| App Store 样本 | 评价数 | 旧版命中 | 新版命中 | 漏判数变化 | 误判数变化 | 查全率变化 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 独立验收，2 个应用 | 16 | 3/12 | 4/12 | 9 → 8 | 0 → 0 | 25.0% → 33.3%，+8.3 个百分点 |
| 回归，4 个应用 | 32 | 4/26 | 20/26 | 22 → 6 | 0 → 0 | 15.4% → 76.9%，+61.5 个百分点 |
| 回归，3 个应用 | 30 | 2/20 | 17/20 | 18 → 3 | 0 → 0 | 10.0% → 85.0%，+75.0 个百分点 |
| 回归，3 个应用 | 36 | 1/28 | 26/28 | 27 → 2 | 0 → 0 | 3.6% → 92.9%，+89.3 个百分点 |

上述 App Store 样本中新旧命中的记录均为已标注的有效证据。独立样本仍漏掉投屏异常、功能缺失和部分买断后续费反馈，衡量不同应用上的效果应优先看独立验收行。 [独立应用样例一](https://apps.apple.com/cn/app/id361304891) · [独立应用样例二](https://apps.apple.com/cn/app/id1444383602)

- **V2EX 原帖与回帖。** 三批回归覆盖 11 条原帖和 90 条回帖。原帖保留 10/10 条有效证据，新增剥离 1 条明确自荐。回帖选出 18/21 条有效证据，误纳入 0 条。在标注为存疑的 2 条回帖中，判为独立需求证据的数量为 0。 [原帖及自荐](https://www.v2ex.com/t/1164298) · [普通推荐对照](https://www.v2ex.com/t/1138414)
- **推广筛选。** 上述回归的 4 条明确推广回帖均剥离，包含首次推荐自己的产品及原作者在自荐帖中再次邀请试用，被标注为普通推荐或实际反馈的回帖误剥离 0 条。公开文字支持判断推广行为。账号之间的实际关系依赖可核实的来源证据。 [作者介绍自己的产品](https://www.v2ex.com/t/845245#r_11541668) · [自荐作者后续邀约](https://www.v2ex.com/t/1164298#r_16836676)
- **采集覆盖。** 通过生产采集函数实际读取一个 V2EX 公开主题的 50 条回帖并写入临时 SQLite，用时约 0.37 秒，含网络和入库。旧版对该主题只记录主帖及回复数。这个实测值对应一次请求，会随网络和主题变化。 [实采主题](https://www.v2ex.com/t/943137)

## 字段和标签

| 核对项 | 旧版正确记录数 | 新版正确记录数 |
| --- | ---: | ---: |
| App Store 评价 ID、源站时间 | 各 32/32 | 各 32/32 |
| App Store 应用版本、源站作者 ID | 各 0/32 | 各 32/32 |
| V2EX 回帖 ID、作者 ID、源站时间、评论锚点 | 旧版无回帖字段 | 各 28/28 |
| 可区分自述付费与询价、普通推荐的「已付费」标签 | 旧版无该标签 | 命中 6/6 个付费自述，11 条样本中误标 0 条 |

V2EX 以源站公开接口为字段基准。单独核对了一条带 `@作者 #楼层` 的实际回复，解析出的关联指向正确评论。`已付费` 标签依据原文中的自述。 [被引用的回帖](https://www.v2ex.com/t/1179184#r_17101362) · [引用该楼的回帖](https://www.v2ex.com/t/1179184#r_17102668)

## 运行速度与集成

同一台 Windows 电脑使用 Python 3.11.9 和内存 SQLite，测试 1,461 条归档信号加 22 条 App Store 评论。每项运行 7 次取中位数，从已有数据开始计时。增量对照先预热再改动一条信号，比较清洗和标签处理总耗时。

| 场景 | 旧版中位耗时 | 新版中位耗时 | 耗时变化 | 吞吐量变化（记录/秒） |
| --- | ---: | ---: | ---: | ---: |
| 首次全量 | 60.10 ms | 199.25 ms | +139.15 ms，+231.5% | 24,677 → 7,443 |
| 日常增量 | 59.24 ms | 47.85 ms | −11.39 ms，−19.2% | 25,035 → 30,989 |

30 项自动化测试通过，覆盖历史归档迁移、重复导入、规则复判、真实反馈与推广分流、评价版本更新及独立目录中的 JSONL 执行。另验证本地 HTML 与 CSV 导出能查看判定原因、来源和规则版本。浏览器脚本语法通过检查。

本机复现可使用 `.market-radar/tmp/evidence021_measure.py` 的 `reserve`、`blind`、`frozen`、`final` 和 `timing` 模式。该目录保存此次回放用的原始响应和标注，`evidence021_validate.py` 用于复查字段及生成本地预览。 [规则库使用说明](../rules/README.md)

## 公开网络扩充实测

扩充基线为 `0.2.1.7`，当前规则为 `0.2.1.12`。意图规则从 19 条增至 47 条，另补充开发者自荐和发布邀约的组合条件。采样覆盖小众软件论坛及 ShareX、Joplin、PowerToys、draw.io、Obsidian Tasks、Jellyfin 的公开 Issues。小众软件论坛按主题分批，GitHub 按仓库分批。比较时向两版规则传入同一份来源正文，GitHub 正文可用的前 1,000 字参与回放。

| 样本 | 记录数 | 有效信号命中 | 漏判数变化 | 误纳入数变化 | 明确推广识别 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 小众软件论坛调试 | 36 | 5/20 → 18/20 | 15 → 2 | 1 → 0 | 1/2 → 2/2 |
| GitHub ShareX 调试 | 17 | 0/16 → 16/16 | 16 → 0 | 0 → 0 | 此批无推广样本 |
| 小众软件论坛第一批复测 | 60 | 6/24 → 17/24 | 18 → 7 | 1 → 1 | 1/2 → 2/2 |
| GitHub Joplin、PowerToys 第一批复测 | 19 | 1/18 → 17/18 | 17 → 1 | 0 → 0 | 此批无推广样本 |
| 小众软件论坛第二批复测 | 30 | 1/7 → 6/7 | 6 → 1 | 0 → 0 | 2/2 → 2/2 |
| GitHub draw.io、Obsidian Tasks 第二批复测 | 22 | 0/22 → 14/22 | 22 → 8 | 样本均为有效需求 | 此批无推广样本 |
| 小众软件论坛末轮样本 | 37 | 6/11 → 6/11 | 5 → 5 | 1 → 0 | 2/3 → 3/3 |
| GitHub Jellyfin 末轮样本 | 5 | 0/4 → 2/4 | 4 → 2 | 有效需求 4 条，存疑 1 条 | 此批无推广样本 |

小众软件论坛末轮样本有一条自荐写在正文里，首次运行时被两版均误纳入。根据作者明确分享自制软件的表达补规则后，针对原帖复测成功。换到这批主题后，有效信号召回仍为 6/11，间接问法和简短的产品比较仍有漏判。GitHub 的空模板、默认提示、引用和代码块有回归用例。 [正文自荐案例](https://meta.appinn.net/t/topic/71367) · [GitHub 漏判案例](https://github.com/jellyfin/jellyfin/issues/18780)

- **原有回归。** 215 条 V2EX 和 App Store 记录的新旧证据状态、意图标签逐条一致。33 项自动化测试通过。
- **采集实测。** 小众软件论坛现接入日常发现流程。单次试采得到 4 条主帖和 18 条回帖，用时 1.28 秒。18 条均有来源链接、源站时间和作者 ID，其中 5 条取得明确的回帖引用关系。 [公开求助板块](https://meta.appinn.net/c/wen-ti-qiu-zhu/7)
- **规则耗时。** 同一台 Windows 电脑，每项运行 9 次取中位数。对 1,513 条记录的无缓存规则回放从 180.01 ms 增至 255.81 ms，约慢 42.1%。在 1,498 条记录的内存 SQLite 集成测试中，预热后只改一条信号的增量处理从 44.28 ms 增至 45.57 ms，增加约 2.9%。两项均从已取得的数据开始计时。

本机可用 `.market-radar/public-rule-replay/replay.py` 的 `dev`、`holdout`、`blind`、`reserve`、`parity`、`speed` 和 `incremental` 模式回放。样例快照、标注和旧版执行器保存在同一目录。

## 评论意图与主题标签复测

`0.2.1.13` 相对 `0.2.1.12` 新增 21 类评论意图和 17 类主题标签。评论可以同时标出故障复现、授权咨询、退款求助等表达，以及同步、备份、数据恢复等主题。修复确认、更新说明、操作建议和普通推荐可用于检索。这些意图单独命中时，证据状态为背景线索。

24 条定向回放样例包含 14 条 App Store 评价和 10 条公开论坛回帖。能识别意图的评论从 14 条增至 20 条。新版命中样例中预先核对的 16 个细分意图和 24 个主题标签。逐条核对证据状态的 23 条样例中，有效证据命中从 13/16 增至 16/16，误纳入从 1/7 降至 0/7。主题标签测试核对的是这批样例中列出的标签。 [修复确认样例](https://meta.appinn.net/t/topic/79689/10) · [退款评价所在应用](https://apps.apple.com/cn/app/id1569376400)

原有 215 条回归记录的独立需求判定一致。对其中 204 条评论单独做无缓存规则回放，9 次中位耗时从 9.58 ms 增至 20.63 ms。35 项自动化测试通过，已验证关键词搜索、意图与主题组合筛选，以及本地 HTML 和 CSV 标签导出。
