# Market Radar 0.2.0 开发计划

从 `v0.1.0`（`3b5cc0f`）在 `dev` 上开发，使用规则处理数据。

## 本版本主要功能

- **精细时间。** 分别记录发帖、评论和采集时间，用可核实的时刻支持「近 24 小时」筛选。信号和评论分别统计时效。
- **采集与评论分库。** 应用和视频写入信号库，采到的 App Store 评价和 B 站留言写入评论库。按平台评论 ID 去重，按应用页或视频链接关联原帖。在信号库点「评论（N）」即可查看。
- **初步用户标签。** 根据获准数据或明确自述标注年龄段、IP 属地、职业和喜好，保留各项依据。在本地详情里可打开已保存的用户主页。

## 开发边界

- 延续 SQLite 增量入库、既有去重规则和 JSONL 归档。保留历史记录、原文和证据 ID，重复导入及失败重试可安全执行。
- 通过增补字段兼容旧库、CSV、立项档案和现有命令。迁移可重复运行，归档失败时保留上一份完整快照。沿用现有看板和页面。
- 沿用现有渠道、搜索词和每日调度。本地提交按采集、评论和文档组织。
- 产品形态评分、聚合和竞品专搜留到后续版本。
- 开发、提交和标签留在本地。仅在收到明确指令后推送、同步或发布。

## Phase 1 时间口径与采集优先级

1. **补充信号时间字段。** 记录原帖发布、评论和采集时间的来源及精度，保留历史原值。
2. **按范围整理时间下拉框。** 顺序为近 24 小时、近 7 天、近 30 天、近 180 天、超过 180 天、时间待核实、全部时间。默认近 7 天。旧信号沿用归档的 `published_at`，在页面标注「归档标记」并按日分档。近 24 小时使用带具体时刻和时区的源站时间。
3. **先排序再取样。** B 站、微信和 V2EX 在已返回的结果中，按可核实的源站时间由新到旧排序，时间不明的排后并沿用源站相对顺序。使用原有取样上限。对应 `feat(discovery)`。

## Phase 2 用户评论

4. **保存评论及原帖关联。** 在 SQLite 和 JSONL 中保留评论原文、来源、时间及原帖链接。有评论者主页链接时一并保存，重复导入时去重。
5. **接入自动采集和 CSV 导入。** App Store 日常和批量采集均以应用为主记录，B 站常规和深挖采集均以视频为主记录。新采评论单独落库，延续各渠道的现有取样范围。CSV 保留手动补录入口。
6. **在原帖快照展开评论。** 通过视频 ID、笔记 ID 或可唯一匹配的原帖链接关联。合并展示时，可选按发帖或当前筛选内的最新评论排序。由评论带入列表的原帖同时显示原帖时间与评论时间。无法匹配的评论可从「仅看评论」点开原帖。

## Phase 3 用户标签

7. **验证数据来源和字段覆盖。** 用获准使用的接口、导出或市场部补录的 CSV 试点，核对四项字段的来源和可用程度。
8. **按规则给评论贴标签。** 将明确的年龄归入年龄段，记录平台展示的 IP 属地，以及用户明确表达的职业和喜好。每项单独保留依据，缺失项标为未知。态度和意图依据评论原文判断。
9. **接入现有信号页和 CSV。** 记录样本中每项有依据的评论数及占比，供人工复核。
10. **在评论详情提供主页和原评论链接。** 有可用链接时，可在新标签页打开。评论和主页链接随本地 HTML 导出。
11. **在人群与时效页分别统计信号和已导入评论。** 按各自的时间统计有效记录，使用互斥的近 24 小时、近 7 天其余、8–30 天、31–90 天、91–180 天、超过 180 天和时间待核实分档。
