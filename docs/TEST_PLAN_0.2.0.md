# Market Radar 0.2.0 测试计划

对应 [0.2.0 开发计划](DEV_PLAN_0.2.0.md) 的 3 个 Phase。按功能提交验证，用同一套回归样本在本地 `test` 验收。

## 测试准备

- 在本地临时目录复制 `v0.1.0`（`3b5cc0f`）的 JSONL、CSV 和立项档案，用旧版结构准备 SQLite 测试库。记录基线条数、证据 ID 和原文链接。
- 使用固定基准时间、带时区的时间样本、旧帖及评论样本。导入、归档和导出在临时目录验证。

## 本地验收结果

2026-11-25，本地验收覆盖时间筛选、自动采集分库、原帖关联和初步用户标签。

- **单元测试。** `python -B -m unittest discover -s tests -v` 共 22 项通过，覆盖自动采集分库、重复采集去重、公开导出隔离和向导入口。
- **重复恢复编号。** 在含 1,365 条信号的数据库副本中连续恢复三次，现有 ID 和自增计数保持一致。新增一条信号时只分配一个新编号。
- **本地向导。** 用实采的 App Store 样本验证菜单 `[6]` 调用导出命令、生成含 3 条评论的本地工作台，并请求浏览器打开该页面。
- **Windows 启动。** 直接运行 BAT 验证本地便携解释器和 PATH 中的 Python 均可打开菜单。没有可用解释器时会提示原因。
- **浏览器。** 用隔离临时库生成本地 HTML。Edge 无头模式验证排序切换、两层时效卡片、第一列的完整时间戳、原帖展开和回环地址上的测试主页。
- **样本范围。** 采集排序、B 站留言和用户标签使用离线样本。App Store 用两个现有检索词免登录实采，并在本地预览验证应用与评价关联。

### 归档日期口径复验

用原归档生成预览，1,331 条有效旧信号均按原 `published_at` 分档并显示「归档标记」，「时间待核实」由 1,331 条降为 0 条。Edge 验证这批旧信号均未计入「近 24 小时」。
